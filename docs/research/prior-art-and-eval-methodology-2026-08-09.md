# Prior art and eval methodology — research record, 2026-08-09

Three questions, researched 2026-08-09 by four parallel read-only agents (method and limitations in [../METHODS.md](../METHODS.md), entry 2026-08-09): (1) does anyone ship a delegation-steering artifact like this plugin; (2) has model selection or steering config been assessed empirically — controlled comparison, not judge-only; (3) what do the strongest primary sources actually prescribe for eval methodology. Confidence labels are preserved from the agents' reports; **UNVERIFIED** means no primary source was successfully read for that claim.

## 1. Prior art — verdict: partially novel

The idea "tier subagents by task type" is crowded; the enforcement mechanism is not.

- **[tzachbon/claude-model-router-hook](https://github.com/tzachbon/claude-model-router-hook)** (source read directly): PreToolUse hook on Agent/Task that classifies prompts with a regex/keyword heuristic and **rewrites** the model field via `updatedInput`, plus a plain-text decision log and a CI-gated 70-row labeled eval set. Its source names "never denies" as an explicit requirement — an author in this exact space considered hard denial and rejected it. Nearest architectural neighbor to this plugin.
- **[CodeShuX/tokenwise](https://github.com/CodeShuX/tokenwise)** (README + file tree read): skills-only 3-tier ladder, NDJSON per-delegation ledger (functionally equivalent to this plugin's ledger, framed as cost-proof), and an on-demand `/ab` command running one task at multiple tiers. No hooks at all.
- Others surveyed: model-matchmaker (advisory predecessor, UNVERIFIED beyond summary), "Gearbox" (UNVERIFIED — no repo located), wshobson/agents and similar static catalogs (pinned `model:` frontmatter, no enforcement), serving-layer routers (musistudio/claude-code-router and kin — different category: proxy routing by request type, not per-delegation steering), Anthropic's own `CLAUDE_CODE_SUBAGENT_MODEL` (one flat model for all subagents).
- **Genuinely unclaimed as of this sweep:** hard denial as the enforcement mechanism, Workflow-script linting at launch, and standing drift detection against Anthropic's live docs. Novelty language anywhere in this repo must stake no more than these three specifics.
- Platform context: recurring upstream demand for native routing (anthropics/claude-code#27665 consolidating 30+ duplicates, #44976, #67898) and instability precedent (#31027: Agent-tool `model` schema regression; #44412: `updatedInput` reportedly ignored for the Agent tool — which would silently disable rewrite-based routers while leaving deny-based gating intact). Feeds the sunset criterion in the plugin README.

## 2. Empirical assessment — model selection and steering config

**Model-tier selection: no controlled study exists for the specific Haiku/Sonnet/Opus question.** The strongest adjacent work: [RouterBench](https://arxiv.org/abs/2403.12031) (405k+ outcomes, deterministic exact-match grading, finding that naive routers often lose to "always pick one model"); [RouteLLM](https://arxiv.org/abs/2406.18665) (ICLR 2025 — cheap-model-when-sufficient routing trained on human Chatbot Arena preferences); [aider's architect/editor pairings](https://aider.chat/2024/09/26/architect.html) (matched Exercism task sets graded purely by passing test suites — the cleanest in-harness paired comparison, apparently single runs per config). [FrugalGPT](https://arxiv.org/abs/2305.05176) reports large cascade savings but its grading method is UNVERIFIED (full text not read). Anthropic's [model-choice docs](https://platform.claude.com/docs/en/docs/about-claude/models/choosing-a-model) are decision-framework prose that explicitly delegates benchmarking to the reader; Anthropic's multi-agent research post reports "Opus lead + Sonnet subagents beat solo Opus by 90.2%" on an internal, LLM-judge-graded eval that confounds architecture with tier. Consequence: the tier-policy study drafted in [../../evals/delegation-tiering/routing-impact-study/PROTOCOL.md](../../evals/delegation-tiering/routing-impact-study/PROTOCOL.md) would measure something not in the literature.

**Steering-config ablation: strong precedent, sobering base rates.** ["Do Context Files Help Coding Agents?"](https://arxiv.org/html/2607.27250) — 288 runs, 3 context strategies × 3 repeats, hidden-gold-test grading, rigorous null statistics: context files did not measurably move correctness but cut runtime ~29% and tokens ~17%. [SWE-Skills-Bench](https://arxiv.org/abs/2603.15401) — paired with/without-skill over deterministic acceptance tests: 39/49 public skills ≈ zero effect, 7 helpful (to +30pp), 3 harmful (to −10pp, version-mismatched guidance). [SkillsBench](https://arxiv.org/abs/2602.12670) — curated skills +16.6pp across 18 configs. A CTF-agent skills ablation ([arXiv:2605.20023](https://arxiv.org/pdf/2605.20023)) shows how wide small-sample CIs run (+8.9pp, CI [−6.8, +24.6]). **All stamped on pre-Claude-5 models — method precedents, but priors rather than conclusions for current models.** This sets the prior for this repo's verdict tickets: a ceremony verdict (component shows no measurable effect) is the published norm across these studies, not a sign this plugin's components are failing.

## 3. Eval-methodology doctrine — strongest primary sources per claim

**Deterministic first; judge is the weaker signal.** Ian Webster (promptfoo creator): "Because programmatic evaluation is cheap, quick, and deterministic, it should be preferred whenever possible" ([ianww.com, 2023-05-21](https://www.ianww.com/blog/2023/05/21/prompt-engineering-framework)). Braintrust docs: "Where possible, implement deterministic quality checks through code-based scoring functions" ([braintrust.dev](https://www.braintrust.dev/docs/best-practices/scorers)). Husain & Shankar: "Start with cheap code-based checks where possible: regex patterns, structural validation, or execution tests" ([hamel.dev evals FAQ](https://hamel.dev/blog/posts/evals-faq/)).

**Judges require validation against human labels.** Primary: Shankar et al., "Who Validates the Validators?" ([arXiv:2404.12272](https://arxiv.org/abs/2404.12272), UIST 2024) — "LLM-generated evaluators simply inherit all the problems of the LLMs they evaluate, requiring further human validation," and the **criteria drift** finding: "users need criteria to grade outputs, but grading outputs helps users define criteria" (abstract verbatim, cross-verified over two mirrors; body-text quotes UNVERIFIED — PDF unparseable by the fetch tooling). Follow-up: Guerdan et al. ([arXiv:2503.05965](https://arxiv.org/abs/2503.05965), NeurIPS 2025) — standard human-judge-agreement validation under forced choice can select judges "as much as 31% worse." Operationalized by Husain & Shankar: measure judge TPR/TNR on a held-out labeled set. This is the doctrine behind [issue #13](https://github.com/TheRealBillSiegler/claude-plugins/issues/13), which blocks all component verdicts until the grading instruments are calibrated.
**Judge bias (why grading here is blind and mechanical):** position/verbosity/self-enhancement bias ([arXiv:2306.05685](https://arxiv.org/pdf/2306.05685) — which also found reference-guided judging cut judge failure on math from 70% to 15%, re-verified from the paper text 2026-08-09); order-swap ranking reversal ([arXiv:2305.17926](https://arxiv.org/abs/2305.17926)); verbosity bias ([arXiv:2310.10076](https://arxiv.org/pdf/2310.10076)); self-preference bias ([arXiv:2410.21819](https://arxiv.org/abs/2410.21819)).

**Eval cases from production failures.** Husain & Shankar: "Write evaluators for errors you discover, not errors you imagine." Anthropic engineering ([Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents), 2026-01-09): "20-50 simple tasks drawn from real failures is a great start"; "If you're already in production, look at your bug tracker and support queue." OpenAI eval guidance: "mine your logs for good eval cases." This is the doctrine behind the ledger-as-production-feed growth rule in [../../evals/README.md](../../evals/README.md).

**Paired comparison for model/config changes.** Chatbot Arena ([arXiv:2403.04132](https://arxiv.org/abs/2403.04132)) grounds pairwise voting in rubric-consistency across raters (rationale quote UNVERIFIED — PDF parsing failed; design itself uncontested). Aider's benchmark holds the task set constant across model/format pairs with deterministic test-suite grading ([aider.chat/docs/benchmarks.html](https://aider.chat/docs/benchmarks.html)). Anthropic docs list "A/B testing: Compare performance against a baseline model or earlier version" as a quantitative method ([define-success](https://platform.claude.com/docs/en/docs/build-with-claude/define-success)) — a one-line mention, not an argued case.

**Anthropic's official eval-building guidance** ([develop-tests](https://platform.claude.com/docs/en/docs/build-with-claude/develop-tests)): "Automate when possible… (multiple-choice, string match, code-graded, LLM-graded)"; "Prioritize volume over quality: More questions with slightly lower signal automated grading is better than fewer questions with high-quality human hand-graded evals"; use "a different model to evaluate than the model used to generate." Notably docs-silent on production-drawn cases — that guidance lives only in the engineering blog post above.

**Matt Pocock (aihero.dev, Evalite)** — retained as practitioner corroboration, ranked below the sources above. His hierarchy from primary pages: deterministic evals first; LLM-as-judge is "more like a smoke test than a real test (personal opinion)"; vibes-checking changes is "a dangerous way to work"; eval data should come from users in a feedback flywheel. He prescribes paired comparison for model/harness swaps ("run two… get an agent to pick the best output, or use human review… tally the results at the end of the week") with judge-or-human as interchangeable arbiters — i.e., his A/B prescription composes with LLM-as-judge rather than opposing it. **Provenance note:** the two tweets quoted (2025-09-06 "evals are dead" and 2026-06-21 run-two) were retrieved via a tweet-mirror API after x.com returned HTTP 402 to direct fetches; content is public and attributed, the retrieval route bypassed X's programmatic-access restriction, disclosed here.
