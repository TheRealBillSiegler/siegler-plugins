# Study protocol — delegation-stack routing impact

Owner decisions pending are marked ⬜. Method: self-contained — the decision rules, endpoints, and floors written in this file govern the study; the repo's evidence bar is [../../README.md](../../README.md) § Ablation protocol. This record lives here because evidence travels with the artifact it judges.

## Question

Does the delegation stack — the delegation rule + delegation-tiering/model-selection skill + agent-model-gate hook — earn its place on current-generation models? Three measurable layers:

1. **Prose effect:** does the rule+skill change which (model, effort) workers choose, versus no delegation steering?
2. **Direction:** when routing changes, does it move toward or away from blind gold labels?
3. **Hook catch rate:** in the prose-only arm, how often does routing violate the rule — the empirical frequency the deterministic gate exists to catch?

The owner's prior ("the model does not do this better natively") is the hypothesis under test and is allowed to lose. All three outcomes are live: load-bearing, expired ceremony, or mixed across layers.

## Relation to the existing eval

[../scenarios.md](../scenarios.md) (baseline 2026-08-06: haiku 12/12, sonnet 12/12) measures **compliance**: workers given the skill match the skill's expectations. This study measures **impact**: whether skill-steered routing beats unsteered routing against *independent* gold. The existing scenarios seed the probe set; their Expected column is skill-derived and is therefore **excluded from gold** — using it would grade the skill with itself.

## Design

- **Paired arms:** control = steering context including the delegation stack; ablated = same context with the stack removed. Same scenarios, same reps, both arms.
- **Scenarios:** the 12 existing tier-eval scenarios + ~15 elicited from real session history (actual tasks that led to Agent/Workflow spawns), spanning trivial lookups → mechanical edits → research → hard judgment. ⬜ final count set by the power derivation.
- **Mechanical primary endpoint — no LLM judge:** workers emit their delegation plan; the chosen (model, effort) is extracted by code. The entire judge-bias caveat class exits the design.
- **Blind gold labels:** before any arm runs, the owner labels the optimal (model, effort) per scenario, seeing only scenarios — never the skill text during labeling, never any arm output. **Recorded limitation — rater contamination:** the owner authored the skill and knows its ladder; blind labels are independent of the *run*, not of the *doctrine*. Mitigation: an outcome-anchored subset — run selected tasks at both candidate tiers and let measured success/cost adjudicate — carries extra weight exactly where owner labels and unsteered choices disagree.
- **Isolation:** workers sandboxed in isolated per-arm configuration (prepared config directories; see [../../../docs/research/arm-isolation-2026-08-09.md](../../../docs/research/arm-isolation-2026-08-09.md)).

## Endpoints and verdict rules (mechanical)

**Primary — routing correctness.** Per scenario×rep pair, each arm's choice scored correct/incorrect against gold.

- *Discordance rate d* = fraction of pairs where arms chose differently (behavioral change, direction-free), with exact CI.
- *Direction:* among discordant pairs, b = flips toward gold, c = flips away; McNemar exact test; effect size = match-rate delta with CI.

Verdict buckets, decided by the numbers:

- **UNCHANGED** — CI(d) entirely below the equivalence margin ⬜ δ (proposed 0.10): an affirmative equivalence claim, not merely "nothing detected."
- **NET POSITIVE** — d above δ and b > c at α ⬜ (proposed 0.05).
- **NET NEGATIVE** — d above δ and c > b at α.
- **DIFFERENT** — d above δ, direction CI covers zero: behavior changed without getting more or less correct. First-class finding.
- **UNRESOLVED** — floors violated (reps, worker-failure limits); never rounded into the four.

**Secondary — cost.** Tokens (and derived $) per delegation, per arm, from the chosen tiers. Same rigor — distributions, deltas, CIs — never merged into the primary verdict ⬜ (owner ruling requested; recommended: separate axis). Banner states both axes jointly: "net positive on routing (+18 pts, CI [8, 28]), at +22% median token cost."

**Power:** reps and scenario count derived before running from the smallest delta worth detecting ⬜ (proposed: 25-point match-rate difference, power 0.8, α 0.05) — derivation printed in the report, not asserted.

## Deliverable — one HTML report as the entry point

A single self-contained `report.html` (inline CSS/JS, no external requests, theme-aware), **generated by a renderer script from the data — computed, not authored**:

1. **Verdict banner** — the two-axis sentence: outcome bucket with effect size and CI, cost delta alongside.
2. **Pre-registration** — decision rules quoted verbatim with this file's approval-time content hash.
3. **Outcome axis** — discordance and direction analyses, per-category breakdowns, charts.
4. **Cost axis** — per-arm token/$ distributions and deltas.
5. **Drill-down** — expandable per-scenario rows: each rep, each arm's choice, gold, agreement (native `<details>`).
6. **Raw observations** — full table; dropped/failed observations itemized.
7. **Methodology and provenance** — this protocol, workflow scripts, raw JSON, stamps, deviations. Everything re-runnable.

Orchestrator commentary only in a clearly marked "notes" section, visually separate from computed content.

## Prerequisites, in order

1. Doc-alignment pass on the delegation-tiering/model-selection skill (test what you'd ship, not stale wisdom).
2. Tally script: code, not judgment, computes every number the verdict depends on — the discordance rate and its confidence interval, the direction test, and the pre-run power check, all as defined under Endpoints above. The verdict bucket then falls out of arithmetic; no eyeballed thresholds.
3. Renderer script: data JSON → report.html, deterministic.
4. Owner gold labels (blind), then frame approval → this file freezes, hash stamped.

## Archival

Protocol, workflow scripts, raw structured outputs, compiled data JSON, and report.html live together in this directory; the report links every layer. Stamped with pipeline config, orchestrator model, and date; verdicts expire on model change.
